Este capítulo se escribió originalmente alrededor de la interfaz de línea de comandos (CLI) de Gemini antes de esa fecha, pero desde entonces se ha actualizado completamente para reflejar Antigravity CLI/Escritorio en la fecha actual. 1. Definición de subagentes — Predefinidos vs. creación dinámica

La familia Anthropic (Claude Desktop App/Claude Code) predefine cada subagente como un único archivo markdown en la carpeta del proyecto. La familia Google (Antigravity Escritorio/CLI) no tiene un archivo de definición separado — el orquestador crea subagentes al vuelo según el objetivo dado. A continuación, cubriremos primero Claude Desktop App y Antigravity(Escritorio) como base, y luego presentaremos el equivalente de CLI de cada uno.

El método concreto de definición/invocación para la familia Claude se cubre en §1-A Centrado en Claude, y el método concreto para la familia Antigravity se cubre en §1-B Centrado en Antigravity.

Campo del frontmatterClaude Desktop App / Claude Code (.claude/agents)Antigravity (Escritorio/CLI)
name Obligatorio. Debe coincidir con el valor de subagent_type para ser invocable No aplicable — no existe archivo de definición; el orquestador determina el rol y alcance de herramientas por sí mismo en tiempo de ejecución para crear el subagente
description Explica cuándo se utiliza este agente; se referencia para decisiones de activación automática
tools Lista de herramientas disponibles; hereda el conjunto predeterminado si se omite
model Especifica un alias como sonnet / opus / haiku
Antigravity (Escritorio/CLI) no tiene en absoluto el concepto de "archivo de definición de subagente" — forzar un ejercicio introductorio que replique el ejemplo reviewer.md de Claude Desktop App/Code en Antigravity sería una tergiversación de los hechos. El "ejercicio introductorio" para Antigravity no consiste en crear un archivo, sino en darle un objetivo y observar cómo el orquestador descompone el trabajo por sí solo.

2. Invocación/delegación de subagentes

La familia Anthropic (Claude Desktop App/Claude Code) inicia un subagente en un contexto separado utilizando la herramienta Agent/Task. La familia Google (Antigravity Escritorio/CLI) delega un objetivo a un agente a través de la interfaz del Administrador de agentes o comandos de barra diagonal.

El método concreto de invocación para la familia Claude se cubre en §1-A Sección 2, y el método concreto para la familia Antigravity se cubre en §1-B Sección 2.

3. Ejecución en paralelo — Comparación de 4 herramientas

Las cuatro herramientas admiten ejecución en paralelo, pero el enfoque difiere. La familia Claude utiliza equipos de agentes / múltiples llamadas Agent, mientras que la familia Antigravity utiliza el Administrador de agentes / paralelismo entre sesiones.

Ejecutar múltiples agentes simultáneamente en el mismo directorio/espacio de trabajo puede causar "superposición cognitiva" — un problema donde un agente confunde la salida de otro agente que trabaja en la misma carpeta como su propio contexto de trabajo (alucinación). Aislar agentes por espacio de trabajo o worktree es la práctica recomendada, y no es un problema menor que pueda omitirse como excepción.

El método de ejecución en paralelo de la familia Claude se cubre en §1-A Sección 3, y el método de ejecución en paralelo de la familia Antigravity se cubre en §1-B Sección 3.

ElementoAntigravity (Escritorio)Claude Desktop App (Escritorio)Antigravity CLI (agy)Claude Code (CLI)
Unidad de ejecución en paralelo Agente independiente por espacio de trabajo Equipos de agentes (solo en proceso) Dentro de una sesión + entre sesiones (múltiples terminales) Múltiples llamadas Agent en un mensaje / Equipos de agentes (en proceso + tmux)

4. Automatización/ganchos — Lo que se ejecuta automáticamente

Claude Code (CLI) activa automáticamente ganchos de eventos (PostToolUse/TeammateIdle/TaskCompleted), pero Claude Desktop App y Antigravity Escritorio no activan ganchos automáticamente. La interfaz de línea de comandos (CLI) de Antigravity proporciona ejecución no interactiva a través de agy -p e inspección de configuración a través de agy inspect.

Los detalles sobre automatización/ganchos para la familia Claude se cubren en §1-A Sección 4, y los detalles para la familia Antigravity se cubren en §1-B Sección 4.

Consejo práctico: Antigravity tiene una cuota de uso que se renueva periódicamente según el trabajo calculado realizado. Las cifras exactas pueden variar según la cuenta/plan, por lo que es más seguro tenerlo en cuenta al planificar ejecutar múltiples agentes en paralelo durante un período prolongado.

Tanto los equipos de agentes como el Administrador de agentes son funciones en rápida evolución — los nombres de indicadores, el comportamiento predeterminado y las disposiciones de interfaz pueden cambiar con cada versión, así que consulte las notas de la última versión antes de confiar en ellos en un flujo de trabajo de producción.
