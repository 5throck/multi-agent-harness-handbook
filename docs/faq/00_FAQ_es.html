Preguntas Frecuentes · Errores Comunes y Soluciones

Esta página recoge los cuadros de advertencia y consejo dispersos en cada capítulo, ordenados por la frecuencia con que aparecen durante la práctica. Busque primero su síntoma y luego siga el enlace "Detalles" si necesita la explicación original.

Configuración y Entorno

Ejecuté el script de configuración del Capítulo 4 §2, pero algunos elementos muestran ❌.

Independientemente del sistema operativo, setup-common.ts revalida la lista de verificación. En Windows, primero confirme que ejecutó el script con privilegios de administrador; en macOS/Linux, verifique que no olvidó opciones opcionales como --wezterm/--docker. Los registros de instalación se guardan en %USERPROFILE%\workshop-setup-logs\ en Windows.

Detalles: Capítulo 4 §2-A Configuración
Estoy intentando instalar Antigravity CLI globalmente mediante npm, pero no funciona.

A partir del 2026-06-18, el servicio de Gemini CLI fue retirado y reemplazado por Antigravity CLI (agy). agy es un solo binario compilado que no requiere instalación de runtime separada — simplemente descomprímalo y añádalo a su PATH. Las instrucciones de instalación por npm están desactualizadas.

Ejecución de Subagentes

Hice que el subagente redactor escribiera un archivo, pero el revisor dice "el archivo no existe."

Lo más probable es que invocó al redactor y al revisor al mismo tiempo (en paralelo) dentro de un solo mensaje. El revisor intentó su revisión antes de que el redactor hubiera creado el archivo, causando el fallo. Para tareas con dependencias, solicite explícitamente la ejecución secuencial, por ejemplo "ejecuta estos dos pasos en orden."

Detalles: Capítulo 4 §2-A D-1
Después de guardar un archivo en Claude App, el script de auditoría no se ejecuta automáticamente.

Esto es esperado. Hooks como PostToolUse/TeammateIdle/TaskCompleted no se activan en Claude App (Escritorio) — solo se ejecutan automáticamente en sesiones de Claude Code (CLI). Los equipos que usan la Aplicación de Escritorio deben ejecutar manualmente lo que el hook habría hecho después de que termine la sesión. Pasar esto por alto puede llevar a incidentes donde se asume "la auditoría se ejecutó" cuando en realidad no lo hizo.

Detalles: Referencia Común §1, Capítulo 3 §Registro de Auditoría y Observabilidad
Le pedí al revisor que solo revisara, pero modificó el archivo de todos modos.

Verifique si el campo tools incluye Write. Para roles de solo lectura como el revisor, conceda desde el principio solo los permisos mínimos necesarios — por ejemplo tools: Read, Grep — de modo que incluso si el prompt se interpreta de manera ambigua, el agente sea estructuralmente incapaz de hacer ediciones.

Detalles: Capítulo 3 §Principio de Mínimo Privilegio
El agente sigue repitiendo la misma tarea y nunca termina.

Este es un estado de bucle en un ciclo evaluador-optimizador, donde el evaluador sigue juzgando la salida "insuficiente" y el optimizador sigue reintentando. La solución: establecer un número máximo de iteraciones por adelantado, y terminar automáticamente si los criterios no se cumplen dentro de ese límite. En lugar de resolver esto a nivel de patrón individual como se describe en el Capítulo 2 §Patrones de Orquestación, es más fácil prevenirlo estructurando todo el flujo de trabajo como un Plan de Ejecución, como se describe en el Capítulo 9.

Detalles: Capítulo 2 §Patrones de Orquestación, Capítulo 9 · Patrones de Diseño de Flujos de Trabajo
Un subagente llama a una herramienta, falla, y luego simplemente se detiene.

Hay dos causas comunes. Primera, un tiempo de espera de red — la llamada a la API o la conexión al servidor MCP se interrumpió brevemente. En Claude Code, verifique el estado de la sesión con el comando /cost; en Antigravity, verifique el estado del agente en el Administrador de Agentes, luego reintente. Segunda, un servidor MCP no conectado — verifique si el servidor MCP local está en ejecución usando claude mcp list (Claude Code) o el comando equivalente de estado del servidor para su plataforma. Para errores transitorios, consulte la solución de problemas de tiempo de espera en Costo y Rendimiento.

Detalles: Preguntas Frecuentes · Costo y Rendimiento, Capítulo 3 §Registro de Auditoría y Observabilidad
¿Cómo puedo monitorear y auditar las acciones destructivas de un agente o el historial de modificaciones de archivos en un entorno empresarial?

La ejecución de comandos de terminal y el historial de uso de herramientas del agente deben recopilarse en tiempo real como registros de auditoría del sistema. Para ello, use un demonio de auditoría o técnica de enlace de shell dentro del entorno sandbox para reenviar los registros de ejecución a un servidor de registros remoto. Además, las operaciones destructivas importantes (por ejemplo, eliminar una base de datos, destruir una clave secreta) deben aplicar una Puerta de Aprobación Humana, aislando estructuralmente la operación para que no pueda ejecutarse sin la firma final de un administrador del sistema o parte responsable.

Detalles: Capítulo 3 §Registro de Auditoría y Observabilidad

Paralelismo y Colaboración en Equipo

En el Administrador de Agentes de Antigravity, dos agentes están editando diferentes archivos, pero los resultados se mezclan.

Lo más probable es que asignó ambos agentes al mismo espacio de trabajo (la misma carpeta). Compartir un código base puede causar "superposición cognitiva," donde un agente confunde el contexto de trabajo de otro agente con el suyo. Siempre separe los agentes por espacio de trabajo o por git worktree.

Detalles: Referencia Común §2, Capítulo 3 §Aislamiento
Activé Agent Teams en Claude App, pero no veo la opción tmux.

Esto es esperado. La Aplicación de Escritorio solo soporta teammateMode: in-process; el modo panel dividido tmux solo es adicionalmente soportado en Claude Code (CLI).

Detalles: Referencia Común §1
¿Cómo debe manejar un agente la necesidad de aprobación humana final o entrada intermedia mientras realiza una tarea?

Use el patrón Human-in-the-Loop (HITL). A medida que el orquestador avanza a través de una tarea, se detiene en un punto de decisión crítico o en una operación que requiere autorización (por ejemplo, despliegue, fusión de código), preserva el estado y solicita retroalimentación del usuario. El agente debe estructurar el contexto de la pregunta y la información que necesita al transmitirla, y si se deniega la aprobación o se solicita una revisión, el equipo de agentes debe volver al estado anterior, incorporar la retroalimentación y controlar el flujo para intentar la tarea nuevamente.

Detalles: Capítulo 9 · Patrones de Diseño de Flujos de Trabajo

Espacio de Trabajo / Variante

Ejecuté new-project.ts, pero la scaffolding fue rechazada o las rutas parecen incorrectas.

Es probable que lo ejecutó desde dentro de una carpeta de proyecto en lugar de la raíz del espacio de trabajo. ai-workspace-standards debe clonarse directamente en la raíz del espacio de trabajo mismo (C:\git en Windows, ~/git en macOS/Linux); colocarlo como un submódulo dentro de otra carpeta de proyecto rompe la resolución de rutas.

Detalles: Capítulo 6 §1
El conteo de "Agentes documentados" de bun run agent:verify no coincide con lo que espero.

La tabla de AGENTS.md y la lista real de archivos agents/*.md están des sincronizadas. Verifique si los agentes solo del espacio de trabajo (auditor, gestor de ciclo de vida, etc.) aún permanecen en la tabla, o si un agente recién creado falta en ella.

Detalles: Capítulo 6 D-1
No estoy seguro de si es seguro ejecutar el pipeline de promoción (l2-to-variant-pipeline.ts).

Este comando deja rastros en el historial real de git y es difícil de deshacer. En un entorno de clase o taller, es suficiente que el instructor lo demuestre una vez en lugar de que cada participante lo ejecute. Consulte la Guía del Instructor para más detalles.

Detalles: Ejercicios del Capítulo 12
¿Cómo uso ai-workspace-standards en un entorno de producción real (Docker/Kubernetes)?

Actualmente, ai-workspace-standards solo funciona integrándose directamente con herramientas locales de codificación con IA (Claude Code/App, Antigravity, etc.). El soporte de equipos de agentes por usuario en un entorno Docker o Kubernetes en conjunto con un servicio frontend como Open WebUI está en discusión como una mejora futura, pero aún no se ha implementado. Detalles: Capítulo 8 §5 Hoja de Ruta Avanzada

¿Puedo consolidar memory/MEMORY.md de múltiples proyectos en un solo lugar?

Actualmente, cada proyecto mantiene un memory/MEMORY.md independiente, y una función a nivel del espacio de trabajo para consolidar y organizar la memoria está planificada como una mejora futura. Esto está pensado para abordar la dificultad de identificar tendencias generales entre archivos de memoria individuales a medida que crece el número de proyectos. Detalles: Capítulo 8 §5 Hoja de Ruta Avanzada

Si se actualiza una plantilla de variante, ¿se propaga automáticamente a los proyectos existentes?

No. ai-workspace-standards utiliza un Modelo de Bifurcación. Los cambios a L1 (la plantilla común) no se propagan automáticamente a los proyectos L2 ya con scaffolding ni a las instancias de proyecto en vivo L3. Esto es por diseño para preservar la divergencia intencional, pero crea la carga operativa de aplicar manualmente parches de seguridad o correcciones de errores. Un modelo de adhesión basado en consentimiento y un pipeline de despliegue asíncrono están en discusión como mejoras futuras. Detalles: Capítulo 8 §5 Hoja de Ruta Avanzada

Crear una nueva variante falla la validación de agent:verify o validate-templates.

La causa más común es no mantener la **simetría** entre las declaraciones de agentes. Por ejemplo, si el handoff_to del agente researcher lista writer, entonces el handoff_from del agente writer también debe definir researcher como par correspondiente. También verifique si hay errores de sintaxis JSON en variant.json o campos obligatorios faltantes (como la lista de agentes).

Detalles: Capítulo 11 §Crear una Nueva Variante
¿Cómo se verifica que un equipo de agentes diseñado y construido por uno mismo consistentemente funcione a la calidad prevista en producción?

Necesita construir un banco de pruebas de agentes para evaluar la operación normal. Primero, defina requisitos de entrada representativos y salidas esperadas (un conjunto de datos de referencia). Segundo, ejecute pruebas de regresión automatizadas contra ese conjunto de datos cada vez que modifique un prompt o una regla de agente. Tercero, para la salida en lenguaje natural que es difícil de puntuar cuantitativamente, configure un modelo de alto rendimiento como Juez-LLM, evaluando contra una puntuación cuantitativa preacordada.

Detalles: Capítulo 13 §Proyecto Integrador

Costo y Rendimiento

¿Cuánto cuesta ejecutar un equipo multiagente en tokens?

El costo se determina por la cantidad de agentes × el nivel de modelo de cada agente × la frecuencia de ejecución. La jerarquía de niveles de modelo (tier: high/medium/low) descrita en el Capítulo 5 es el mecanismo clave de control de costos. Por ejemplo, ejecutar los 10 agentes de la variante co-consult en nivel alto puede consumir decenas de miles de tokens en una sola sesión, pero reducir los roles de implementación real a medio/bajo puede recortar los costos entre un 40-60%. El comando /cost de Claude Code permite verificar el uso acumulado de tokens para la sesión actual en tiempo real.

Detalles: Capítulo 5 §Plantillas y las 7 Variantes
Las respuestas de los agentes de repente se vuelven lentas o agotan el tiempo de espera.

Cuando la ventana de contexto se llena, la velocidad de procesamiento del modelo disminuye drásticamente. Claude Code permite comprimir la longitud de la conversación con el comando /compact. Además, al ejecutar múltiples agentes en paralelo, las solicitudes a la API pueden acumularse y causar retrasos — en este caso, cambie a ejecución secuencial o reduzca su límite WIP para disminuir el número de ejecuciones concurrentes.

Detalles: Referencia Común §1
Ejecutar un ciclo multiagente o un flujo de trabajo largo consume demasiados tokens de API. ¿Cómo lo optimizo?

Primero, asigne **niveles de modelo** distintos por rol de agente. Use modelos medio/bajo para escrituras simples de archivos o ejecución de pruebas, y reserve modelos de nivel alto para el control general del flujo o el diseño integral — esto por sí solo puede reducir los costos en un 40% o más. Segundo, mantenga el contexto de la conversación estable para que funcione el caché de prompts — evite cambiar el prompt del sistema y mantenga una sesión continua. Tercero, establezca límites estrictos claros, como Max Turns, para que la conversación entre el orquestador y los especialistas no gire indefinidamente.

Detalles: Capítulo 5 §Plantillas y las 7 Variantes

Problemas Específicos de Plataforma

Ejecutar new-project.ts en Windows produce un error de separador de ruta.

Los scripts de ai-workspace-standards usan el módulo path del runtime Node.js/Bun para manejar rutas específicas de la plataforma, por lo que son compatibles con Windows y macOS/Linux por defecto. Sin embargo, pueden surgir problemas si una ruta estilo PowerShell (C:\Users\...) se mezcla cuando ejecuta git clone directamente dentro de una sesión de Claude Code en lugar de Git Bash. En Claude Code, use siempre rutas estilo / o formato Git Bash, y se recomienda clonar la raíz del espacio de trabajo en una ubicación corta y superficial como C:\git.
