Sub-Agent Usage Details — Codex-Focused

Un documento detallado, limitado a la familia Codex, sobre cómo desempeñar, secuenciar y escalar a automatización el trabajo que corresponde a "subagentes" en Codex CLI / Codex Desktop App  |  Los conceptos compartidos se cubren en la referencia del Cap.4 §1, la familia Claude en Cap.4 §1-A, y la familia Antigravity en Cap.4 §1-B.

Versión objetivoCodex CLI / Codex Desktop App — vea §1-A para el equivalente de Claude, §1-B para Antigravity
URL de documento de referenciadevelopers.openai.com/codex
Documentos recopilados el2026-09-12
Cómo verificar la versiónCodex CLI: codex --version · Codex Desktop App: la pantalla Acerca de de la aplicación
Codex no tiene una herramienta nativa de subagentes. Por eso este documento usa el término "rol" en todo momento en lugar de "subagente" — un subagente como se describe en los documentos de Claude/Antigravity es una entidad independiente con su propio proceso y ventana de contexto, pero un rol que el PM "asume" en Codex es solo un cambio de pensamiento que continúa dentro de la misma sesión. Consulte Comparación de Herramientas §3 para el contexto completo.

1. Definir roles

Codex CLI y Codex Desktop App no requieren crear un archivo de definición de antemano. En su lugar, el PM lee el archivo de definición ya existente de cada agente especialista desde agents/<name>.md en la raíz del espacio de trabajo cuando comienza la sesión, y lo usa como contexto de rol. El formato se parece al .claude/agents/*.md de la familia Claude, pero el propósito difiere — en Claude es una "definición ejecutable" referenciada mediante subagent_type al momento de la invocación, mientras que en Codex es material que el PM carga como referencia, para pensar como ese rol.

Codex Desktop App agents/<name>.md — Contexto de rol de solo lectura

En Codex Desktop App, el PM carga un archivo como agents/reviewer.md del espacio de trabajo directamente en medio de la conversación y declara "voy a trabajar de la forma que este rol define." El archivo en sí puede compartir el mismo formato frontmatter que la familia Claude, pero Codex no lo genera como un subagente ejecutable — es solo un documento referenciado. Codex CLI usa exactamente el mismo archivo de la misma manera — no hay diferencia en cómo se definen los roles entre ambos.

Contenido de agents/reviewer.md (puede
compartir el mismo formato que la
versión de Claude):
---
name: reviewer
description: Revisa archivos de texto en
  busca de errores tipográficos y
  vacíos lógicos.
---

Estás actuando como revisor. Lee el
archivo dado e informa una lista de
mejoras.

Codex CLI — El mismo agents/<name>.md que Codex Desktop App

Referencia exactamente el mismo archivo agents/<name>.md usado en Codex Desktop App. No hay diferencia en el método de definición de roles entre la aplicación de escritorio y la CLI.

Elemento de comparaciónFamilia Claude (.claude/agents)Familia Codex (agents/<name>.md)
Ubicación del archivo .claude/agents/*.md (carpeta específica de la plataforma) agents/<name>.md (carpeta común del espacio de trabajo — sin copia específica de plataforma)
Propósito Definición de subagente ejecutable — invocada vía subagent_type Contexto de rol de solo lectura — el PM lo referencia para pensar como ese rol
Mecanismo de invocación Herramienta Agent/Task Ninguno — el PM simplemente lee el archivo y declara "voy a desempeñar este rol"

2. Desempeñar/cambiar de rol

Ni Codex CLI ni Codex Desktop App generan un subagente con su propio contexto. En cambio, el PM cambia de rol dentro de la misma sesión — avanzando por el trabajo en orden, p. ej. "analiza este archivo ahora como el rol de diseñador, luego escribe el código como el rol de implementador."

Codex Desktop App — Cambio de rol secuencial por el PM

Cuando le pides al PM en Codex Desktop App un trabajo que necesita varias áreas de experiencia, el PM carga el archivo de definición del rol relevante en cada etapa, trabaja desde la perspectiva de ese rol, y luego pasa al siguiente rol. Varios roles nunca existen en paralelo; cada etapa retoma los resultados de la etapa anterior. Codex CLI ejecuta exactamente el mismo enfoque de cambio secuencial — hacer la misma solicitud en una terminal en lugar de una ventana de chat se maneja de forma idéntica.

Usuario: "Revisa la lógica de expiración
de sesión en src/auth/login.ts y corrige
cualquier error que encuentres."

Progresión interna del PM (secuencial,
dentro de una sesión):
1. Carga agents/reviewer.md como contexto
   de rol para revisar el código
2. Resume los problemas encontrados
3. Cambia de rol a agents/automation-
   engineer.md para implementar la
   corrección

Codex CLI — Mismo cambio secuencial que Codex Desktop App

El mismo enfoque exacto de cambio de rol secuencial que Codex Desktop App. Hacer la misma solicitud en lenguaje natural en una terminal se maneja de la misma forma, con el PM cambiando de rol a medida que trabaja.

Copiar los ejemplos de Claude/Antigravity textualmente y decir "Codex invoca el subagente reviewer" para este ejercicio sería inexacto. El "ejercicio introductorio" de Codex no consiste en invocar un subagente — consiste en darle al PM trabajo que necesita varios roles y observar cómo cambia de rol de forma secuencial.

3. Ejecución paralela

La familia Codex no soporta ejecución paralela dentro de una sesión. Cada cambio de rol ocurre en orden, dentro de una única sesión lineal.

Codex no tiene nada equivalente a los Agent Teams de Claude o al Administrador de Agentes/subagentes dinámicos de Antigravity — no hay "paralelismo dentro de la sesión." Para ejecutar varias cosas a la vez, hay que abrir varias terminales (o ventanas) y separar las sesiones mismas — esto se acerca más a colocar varias sesiones independientes una junto a otra que a la ejecución paralela propiamente dicha.

Codex Desktop App — Paralelismo entre sesiones mediante múltiples ventanas

Para trabajar en tareas diferentes al mismo tiempo en Codex Desktop App, abra varias ventanas (o pestañas) de la aplicación, cada una como una sesión separada. Mientras varias sesiones no toquen el mismo archivo a la vez, no hay conflicto. Codex CLI implementa el paralelismo entre sesiones de la misma manera, abriendo varias terminales.

Codex CLI — Paralelismo entre sesiones mediante múltiples terminales

Exactamente el mismo principio que Codex Desktop App. Si una sesión de codex está refactorizando la capa API mientras otra escribe pruebas, no entrarán en conflicto siempre que no toquen los mismos archivos.

ElementoCodex Desktop AppCodex CLI
Unidad de ejecución paralela Sin paralelismo dentro de la sesión / solo paralelismo entre sesiones mediante múltiples ventanas Sin paralelismo dentro de la sesión / solo paralelismo entre sesiones mediante múltiples terminales

4. Automatización/hooks

En la familia Codex, la automatización y los hooks no muestran diferencia entre la aplicación de escritorio y la CLI — ninguna ejecuta el conjunto de hooks del espacio de trabajo en absoluto.

Codex Desktop App — Sin hooks, autoimpuesto vía el prompt

Codex Desktop App no tiene nada equivalente a los eventos de disparo automático de Claude Code como PostToolUse/TeammateIdle/TaskCompleted. La gobernanza — ejecutar scripts de auditoría, aplicar reglas de gate — depende en cambio de que el PM reconozca y lleve a cabo las instrucciones de CODEX.md por sí mismo, en cada sesión (autoimposición vía prompt). Codex CLI es idéntico — no hay mecanismo de hooks en absoluto.

Codex CLI — Misma ausencia de hooks que Codex Desktop App

Exactamente igual que Codex Desktop App. El PM debe reconocer y llevar a cabo por sí mismo las instrucciones escritas en CODEX.md dentro de la sesión (p. ej., "siempre ejecuta bun scripts/audit.ts después de modificar un archivo") — no hay ningún mecanismo que se dispare automáticamente en respuesta a un evento.

# Ejemplo de instrucción en CODEX.md (no se
# dispara automáticamente — el PM la
# reconoce y ejecuta directamente):
# "Siempre ejecuta bun scripts/audit.ts
#  después de escribir/editar un archivo."

bun scripts/audit.ts
Al seguir los ejercicios multiagente de este manual con Codex, lea siempre "invocar un subagente" como "el PM carga el archivo de definición de ese rol y desempeña el rol," y "el hook se dispara automáticamente" como "el PM reconoce y lleva a cabo las instrucciones de CODEX.md por sí mismo."
