Comparación de Herramientas — Claude Code / Claude App / Antigravity CLI / Antigravity

Incluso el mismo "equipo multi-agente" funciona de forma diferente y encuentra diferentes restricciones según la herramienta con la que se construya  |  Documentación oficial: Claude Code, Antigravity CLI, Antigravity Agent Manager

A partir del 2026-06-18, Google discontinuó el servicio de Gemini CLI para usuarios individuales (Gratis/Pro/Ultra), y Antigravity CLI (agy) tomó su lugar. Este manual fue escrito originalmente alrededor de la interfaz de línea de comandos de Gemini antes de esa fecha, pero se ha actualizado completamente a la interfaz de línea de comandos de Antigravity a la fecha actual. Si encuentra el comando gemini o una ruta .gemini/agents/ en material antiguo, trátelo como una referencia a una versión que ha sido reemplazada.

Las Cuatro Herramientas en Resumen (Escritorio Primero, CLI en Paralelo)

Familia Anthropic

1. Claude App (Escritorio) vs Claude Code (CLI)

Este manual trata a Claude App (Escritorio) como su herramienta práctica predeterminada. Dado que el flujo de creación e invocación de subagentes a través de la GUI es el mismo, puede seguir el contenido a continuación igual de fácilmente usando Claude Code (CLI). Ambas herramientas funcionan con el mismo motor de Claude, pero dado que sus entornos de ejecución difieren, algunos de los mecanismos que componen un arnés multiagente solo funcionan en la CLI. Las mayores diferencias están en los hooks de automatización y los modos de ejecución de Agent Teams.

Claude App (o Claude Code) — Subagentes .claude/agents/*.md

Claude App define subagentes personalizados a través de archivos .claude/agents/*.md y los invoca con la herramienta Agent/Task, exactamente igual que Claude Code. Sin embargo, los hooks PostToolUse/TeammateIdle/TaskCompleted definidos en .claude/settings.json no se activan en Claude App. Solo se activan automáticamente en eventos como guardar archivos o completar tareas dentro de una sesión CLI. Los equipos que usan Claude App deben ejecutar manualmente lo que el hook habría hecho (por ejemplo, ejecutar un script de auditoría) después de que termine la sesión.

Veamos un accidente concreto que esta diferencia puede causar. Supongamos que un equipo ha configurado un hook PostToolUse en la CLI para que "cada vez que se guarda un archivo, bun scripts/audit.ts se ejecute automáticamente para detectar fugas de secretos o violaciones de reglas." Cuando el mismo miembro del equipo hace la edición idéntica en Claude App (Escritorio), el hook nunca se activa — sin embargo, en pantalla se ve exactamente igual que en la CLI: "el archivo fue guardado," sin ningún signo visible de que el hook no se ejecutó. Si ese estado llega hasta un commit, un problema que el hook debería haber detectado se desliza silenciosamente. El verdadero peligro no es "olvidamos ejecutar la auditoría" — es "pensamos que la auditoría se ejecutó, pero no lo hizo."

teammateMode — Claude App Solo Soporta in-process, Claude Code También Soporta tmux

Agent Teams, una función experimental, lanza múltiples instancias de Claude en paralelo. Claude App solo puede usar el modo in-process, que paraleliza dentro del mismo proceso, y algunas navegaciones por teclado (por ejemplo, Shift+Abajo) están restringidas. El modo tmux, que usa un panel dividido de terminal, solo es adicionalmente soportado en Claude Code (CLI).

FunciónClaude App (Escritorio)Claude Code (CLI)
Invocar subagentes mediante la herramienta Agent/Task Soportado Soportado
Subagentes personalizados mediante .claude/agents/*.md Soportado Soportado
Hooks PostToolUse / TeammateIdle / TaskCompleted No soportado (ejecución manual requerida) Soportado (se activa automáticamente)
Agent Teams — teammateMode: in-process Soportado (algunos atajos limitados) Soportado
Agent Teams — teammateMode: tmux No soportado Soportado
Para usar Agent Teams en la Aplicación de Escritorio, debe establecer explícitamente teammateMode en in-process. Las reglas de su equipo también deben reflejar el hecho de que los hooks no se activan. Tenga cuidado de no confundir una auditoría automatizada omitida silenciosamente con un "aprobado."

2. Antigravity (Escritorio) vs Antigravity CLI (agy)

En el lado de Google también, este manual trata a Antigravity (Escritorio) como su herramienta práctica predeterminada. Es una aplicación de escritorio independiente diseñada desde cero para supervisar múltiples agentes en múltiples espacios de trabajo simultáneamente. Antigravity CLI (agy) es la cara CLI de la misma plataforma, estructurada de modo que una sola sesión de terminal recibe un objetivo y lo descompone en subtareas por sí sola. Ambas herramientas también comparten la misma carpeta de configuración (antigravity-cli/ bajo ~/.gemini).

Espacios de Trabajo · Bandeja de Entrada · Zona de Pruebas — Administrador de Agentes de Antigravity (Escritorio)

El Administrador de Agentes de Antigravity es una interfaz de nivel superior que supervisa múltiples espacios de trabajo desde una sola pantalla. El principio es asignar un agente por espacio de trabajo, y los mensajes que necesitan aprobación o retroalimentación se acumulan en la Bandeja de Entrada. La Zona de Pruebas es un espacio para experimentar ligeramente antes de comprometerse con un espacio de trabajo formal. Al lanzar un agente, se elige entre el Modo Local, que trabaja directamente en la carpeta activa, y el Modo Nuevo Worktree, que trabaja en un git worktree aislado.

Aunque puede asignar múltiples agentes al mismo espacio de trabajo (misma carpeta) a la vez, hay informes reales de diferentes agentes confundiendo y mezclando el contexto del código base ("superposición cognitiva"). Es más seguro separar el trabajo paralelo por espacio de trabajo o por git worktree.

Comandos Slash de Antigravity CLI (agy) — /goal, /agent, /agents

A diferencia de Claude Code/App, que predefine subagentes en archivos como .claude/agents/*.md, la interfaz de línea de comandos de Antigravity funciona haciendo que el agente orquestador decida por sí mismo cómo dividir un objetivo en tareas una vez que se le asigna uno, creando subagentes sobre la marcha y ejecutándolos en paralelo. Cada subagente tiene su propia ventana de contexto independiente, evitando que el contexto de la sesión principal se diluya.

Para usar una analogía: Claude Code/App trabaja con "una plantilla precontratada de miembros de tiempo completo," mientras que la interfaz de línea de comandos de Antigravity se acerca más a "contratar un trabajador freelance en el momento para cualquier trabajo que surja." Lo primero facilita el control de permisos porque siempre se sabe quiénes son los miembros del equipo; lo segundo ofrece la flexibilidad de obtener nuevo talento cada vez, pero se necesita una forma de verificar después "quién fue realmente traído esta vez." Eso es para lo que sirve /agents a continuación.

Algo que vale la pena señalar aquí: la capacidad de crear subagentes dinámicamente no es exclusiva de Antigravity CLI. La herramienta Agent(Task) de Claude Code/App también genera subagentes sobre la marcha a partir de solicitudes en lenguaje natural, juzgando qué tarea se necesita en el momento (Capítulo 1 §3b), y el Administrador de Agentes de Antigravity (Escritorio) también permite dar un objetivo en lenguaje natural sin un archivo predefinido (§1). Los comandos /goal·/agent·/agents introducidos en esta sección son simplemente sintaxis para manejar esa misma capacidad de orquestación dinámica mediante comandos slash en la pantalla CLI. Claude Code/App hace lo mismo a través de oraciones en el chat en lugar de esta sintaxis, y Antigravity Escritorio hace lo mismo a través de botones GUI (aprobaciones de Bandeja de Entrada, Zona de Pruebas, etc.) en lugar de esta sintaxis.

A continuación se muestran cuatro comandos slash específicos de CLI que usará frecuentemente al trabajar con agy. Lea la tabla a continuación no como "una lista de funciones exclusivas de Antigravity CLI" sino como "los nombres dados a la misma capacidad en la interfaz de línea de comandos."

ComandoAcción
agyInicia una sesión TUI.
/goal <objetivo>Ejecuta un objetivo hasta su finalización sin confirmación intermedia. El orquestador divide las subtareas por sí solo.
/agent <tarea>Delega una tarea de larga duración a un agente en segundo plano y le permite continuar con otro prompt sin esperar a que termine.
/agentsMuestra una lista de subagentes creados hasta el momento, con su estado de ejecución/completado/bloqueado.

Aquí está el flujo real de iniciar una sesión y ejecutar un objetivo.

agy

Dentro de la sesión (interactivo):

/goal Añade un resumen a cada archivo de texto en esta carpeta

Si, como en CI/automatización, desea una sola ejecución sin conversación (no interactivo):

agy -p "Redacta un mensaje de commit"

También en el lado CLI, es más seguro mantener las sesiones separadas. Si una sesión de agy está refactorizando la capa API mientras otra escribe pruebas, no entrarán en conflicto siempre que no toquen los mismos archivos.

Hay un criterio que separa las dos filas anteriores. ¿El subagente es "una llamada de un solo uso que solo devuelve un resultado una vez delegado" o "una entidad tipo compañero que permanece activa"? La llamada Agent(Task) única de Claude Code/App y los subagentes dinámicos de la interfaz de línea de comandos de Antigravity se acercan más a lo primero. Una vez generados, manejan todo solos hasta el final y solo devuelven un resumen, por lo que no hay forma de dar nuevas instruccaciones a mitad de camino ni hacer que conversen con otro subagente. Los Agent Teams de Claude Code/App, por el contrario, son lo segundo — cada compañero puede enviar mensajes directamente a otro mediante SendMessage (ya cubierto en el ejercicio P-1 del Capítulo 2 §1). Antigravity (Escritorio) no soporta la comunicación entre agentes en absoluto, pero en su lugar permite que un humano converse individualmente con cada agente en progreso a través de la Bandeja de Entrada — esto es lo que lo distingue de las otras tres herramientas.

4. Qué Herramienta Elegir para Este Manual

Este manual lo guía usando Claude App y Antigravity (Escritorio) como sus herramientas prácticas predeterminadas, porque comenzar con una GUI tiene una barrera de entrada más baja. El Capítulo 2 igualmente muestra primero estas dos herramientas de escritorio, y luego sigue inmediatamente con los procedimientos de Claude Code (CLI) y Antigravity CLI (agy) lado a lado. Puede elegir solo una herramienta y seguirla, o comparar y practicar con las cuatro juntas. Los siguientes criterios facilitan la elección.

  1. Si solo quiere familiarizarse primero mediante GUI. Comience con Claude App o Antigravity (Escritorio). Este es el camino predeterminado del manual.
  2. Si necesita supervisar varios proyectos diferentes a la vez. El Administrador de Agentes de Antigravity (Escritorio) (aislamiento por espacio de trabajo) está diseñado exactamente para este escenario.
  3. Si necesita automatización basada en hooks (puertas de auditoría/QA). Cambie a Claude Code (CLI). Claude App y la familia Antigravity no tienen hooks automáticos correspondientes.
  4. Si quiere que un orquestador divida las cosas por sí mismo sin definir subagentes uno por uno. Antigravity CLI (agy) crea subagentes dinámicamente a partir de un objetivo. A cambio, el control granulado es relativamente limitado.

💡 Idea clave: Las cuatro herramientas comparten la misma estructura básica de ingeniería de arnés: "dar a los subagentes un rol estrecho y dejar que un orquestador los coordine." Lo que cambia es en qué entorno de ejecución (CLI/GUI, hooks o no, si los subagentes están predefinidos o creados sobre la marcha) se construye esa estructura.

5. AGENTS.md — Uniendo las Cuatro Herramientas

Los hooks, la ejecución paralela y los métodos de definición de subagentes comparados hasta ahora difieren de herramienta a herramienta, pero la configuración en la raíz del repositorio aún puede unificarse en una sola. AGENTS.md es un estándar abierto creado en agosto de 2025 por OpenAI junto con Google, Cursor y Factory, y donado a la Fundación de IA Agente de Linux Foundation en diciembre de 2025. Es soportado por más de 30 herramientas, incluyendo Codex, Cursor, GitHub Copilot y Google Jules, así como Claude Code (vía importación) y la familia Antigravity.

Colocar un solo AGENTS.md en la raíz del repositorio permite que las cuatro herramientas lo lean al inicio de la sesión y compartan reglas comunes como comandos de compilación/prueba, estilo de código y áreas restringidas. El comportamiento específico de cada herramienta (hooks, teammateMode, dónde se definen los subagentes, etc.) sigue registrándose por separado, como se compara en la tabla anterior, en archivos específicos como CLAUDE.md y GEMINI.md. AGENTS.md maneja el denominador común, y los archivos específicos manejan las diferencias.

ArchivoRolHerramientas que lo leen
AGENTS.md Reglas comunes neutrales a la herramienta (comandos de compilación/prueba, estilo de código, áreas restringidas) Claude Code (importación) · Familia Antigravity · Codex · Cursor · Copilot y más de 30
CLAUDE.md Comportamiento detallado específico de Claude Code/App (hooks, comandos slash, reglas de despacho de agentes) Claude Code, Claude App
GEMINI.md Comportamiento detallado específico de Antigravity CLI/Escritorio Antigravity CLI, Antigravity (Escritorio)

💡 Idea clave: El repositorio ai-workspace-standards descrito en el Capítulo 5 §1 implementa exactamente esta estructura. El AGENTS.md raíz sirve como la única fuente de verdad (SSOT) para la plantilla de agentes, y la carpeta .agents/ se sitúa junto con .claude/·.gemini/, conteniendo comandos y habilidades agnósticas a la herramienta.
