第6章 §1-C

Sub-Agent Usage Details — Codex-Focused

Codex CLI / Codex Desktop Appで「サブエージェント」に相当する作業を遂行し、順次実行し、自動化単位に拡張する方法をCodex系列に限定してまとめた詳細ドキュメント  |  共通概念は第6章 §1 リファレンスで、Claude系列は第6章 §1-Aで、Antigravity系列は第6章 §1-Bで扱う。

対象バージョンCodex CLI / Codex Desktop App — Claude対応は§1-A、Antigravity対応は§1-B参照
参考ドキュメントURLdevelopers.openai.com/codex
ドキュメント収集日2026-09-12
バージョン確認方法Codex CLI: codex --version · Codex Desktop App: アプリの「バージョン情報」画面
Codexにはネイティブなサブエージェントツールがない。本ドキュメント全体で「サブエージェント」という用語をそのまま使わず「役割（role）」という表現を使う理由がここにある — Claude/Antigravityのドキュメントで言うサブエージェントは、独立したプロセス・独立したコンテキストウィンドウを持つ独立した存在だが、Codexで PM が「担う」役割は、同じセッション内で続く思考の切り替えに過ぎない。詳しい背景はツール比較 §3を参照。

1. 役割を定義する

Codex CLIとCodex Desktop Appは事前に定義ファイルを作成する必要がない。代わりに、ワークスペースルートのagents/<name>.mdにすでにある各専門エージェントの定義ファイルを、PMがセッション開始時に読み込み、役割コンテキストとして使う。Claude系列の.claude/agents/*.mdと形式は似ているが用途が異なる — Claudeでは呼び出し時にsubagent_typeで参照される「実行可能な定義」だが、Codexでは PM が参考資料として読み込み、その役割のように考えるための素材だ。

Codex Desktop App agents/<name>.md — 読み取り専用の役割コンテキスト

Codex Desktop AppでPMは、ワークスペースのagents/reviewer.mdのようなファイルを会話中に直接読み込み、「この役割が定義した通りに作業する」と宣言する。ファイル自体はClaude系列と同じfrontmatter形式を共有できるが、Codexがこれを実行可能なサブエージェントとしてスポーンすることはない — あくまで参照される文書だ。Codex CLIでも全く同じファイルが全く同じ方法で使われる — 両者の間で役割定義方法に違いはない。

agents/reviewer.md の内容（Claude用と
同じ形式でもよい）:
---
name: reviewer
description: テキストファイルの誤字と
  論理的な欠陥をレビューする。
---

あなたはレビュアーの役割です。与えられた
ファイルを読み、改善点をリストにまとめて
報告してください。

Codex CLI — Codex Desktop Appと同一のagents/<name>.md

Codex Desktop Appで使ったのと全く同じagents/<name>.mdファイルをそのまま参照する。Desktop AppとCLIの間で役割定義方法の違いはない。

比較項目Claude系列 (.claude/agents)Codex系列 (agents/<name>.md)
ファイルの場所 .claude/agents/*.md（プラットフォーム専用フォルダ） agents/<name>.md（ワークスペース共通フォルダ — プラットフォーム専用コピーなし）
用途 実行可能なサブエージェント定義 — subagent_typeで呼び出す 読み取り専用の役割コンテキスト — PMが参照してその役割のように考える
呼び出しメカニズム Agent/Taskツール なし — PMがファイルを読み「この役割を遂行する」と宣言するだけ

2. 役割を遂行/切り替える

Codex CLIとCodex Desktop Appはどちらも、独立したコンテキストを持つサブエージェントをスポーンする代わりに、PMが同じセッション内で役割を着替える。「今は設計者の役割でこのファイルを分析し、次は実装者の役割でコードを書く」という具合に、段階を順番に踏んでいく。

Codex Desktop App — PMの順次役割切り替え

Codex Desktop AppでPMに複数の専門性が必要な作業を依頼すると、PMは各段階で該当する役割の定義ファイルを読み込み、その役割の視点で作業した後、次の役割へ移る。複数の役割が並列に同時存在することはなく、各段階は前段階の結果を引き継ぐ。Codex CLIでも全く同じ順次切り替え方式がそのまま動作する — チャット画面の代わりにターミナルで同じ依頼をすれば、同様に処理される。

ユーザー: 「src/auth/login.tsのセッション
期限切れ処理ロジックをレビューして、
バグがあれば直して。」

PMの内部進行（1つのセッション内で順次）:
1. agents/reviewer.mdを役割コンテキストとして
   読み込みコードをレビュー
2. 発見した問題を整理
3. agents/automation-engineer.mdに役割を
   切り替えて修正を実装

Codex CLI — Codex Desktop Appと同一の順次切り替え

Codex Desktop Appと全く同じ順次役割切り替え方式だ。ターミナルで自然言語で依頼すれば、同じ方法でPMが役割を着替えながら作業する。

この実習でClaude/Antigravityの例をそのまま真似て「Codexでreviewerサブエージェントを呼び出す」という表現を使うと事実と異なる。Codexの「入門実習」はサブエージェントを呼び出すことではなく、PMに複数の役割が必要な作業を任せ、順次役割が切り替わる過程を観察することだ。

3. 並列実行

Codex系列はセッション内並列実行をサポートしていない。すべての役割切り替えは1つの線形セッション内で順番に起こる。

Claude系列のAgent TeamsやAntigravity系列のAgent Manager/動的サブエージェントに相当する「セッション内並列」はCodexにない。複数の作業を同時に進めたい場合はターミナル（またはウィンドウ）を複数開いてセッション自体を分離する必要がある — これは並列実行というより、複数の独立したセッションを並べて置くことに近い。

Codex Desktop App — 複数ウィンドウによるセッション間並列

Codex Desktop Appで異なる作業を同時に進めるには、アプリのウィンドウ（またはタブ）を複数開き、それぞれ別のセッションとして作業する。複数のセッションが同じファイルを同時に触らない限り競合しない。Codex CLIでも同じ原理で、ターミナルを複数開いてセッション間並列を実現する。

Codex CLI — 複数ターミナルによるセッション間並列

Codex Desktop Appと全く同じ原理だ。1つのcodexセッションがAPI層をリファクタリングしている間に別のセッションがテストを書いても、同じファイルに触れない限り競合しない。

項目Codex Desktop AppCodex CLI
並列実行単位 セッション内並列なし / 複数ウィンドウによるセッション間並列のみ可能 セッション内並列なし / 複数ターミナルによるセッション間並列のみ可能

4. 自動化/フック

Codex系列では自動化・フックはDesktop AppとCLIの間に違いがない — どちらもワークスペースのフックスイートを一切実行しない。

Codex Desktop App — フック未実行、プロンプトで自己強制

Claude CodeのPostToolUse/TeammateIdle/TaskCompletedのような自動発火イベントに対応する仕組みがCodex Desktop Appにはない。監査スクリプトの実行やゲートルールといったガバナンスは、CODEX.mdに明記された指針をPMが毎セッション自ら認識して実行する方式（プロンプト自己強制）で代替する。Codex CLIも全く同じだ — フックの仕組み自体がない。

Codex CLI — Codex Desktop Appと同様にフックなし

Codex Desktop Appと全く同じだ。CODEX.mdに書かれた指針（例：「ファイルを変更した後は必ずbun scripts/audit.tsを実行する」）をPMがセッション内で自ら認識し実行する必要がある — イベントに反応して自動実行される仕組みはない。

# CODEX.mdに書かれた指針の例
# （自動発火ではなく、PMが直接認識・実行）:
# 「ファイルをWrite/Editした後は必ず
#  bun scripts/audit.tsを実行して監査する。」

bun scripts/audit.ts
Codexでこのハンドブックのマルチエージェント実習に取り組む際は、常に「サブエージェントを呼び出す」を「PMが該当する役割の定義ファイルを読み込み、その役割を遂行する」に、「フックが自動発火する」を「PMがCODEX.mdの指針を自ら認識し実行する」に読み替える。
