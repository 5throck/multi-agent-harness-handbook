Hermesのプラットフォーム表面を理解する

Hermes Agentはモデル提供者から独立したCLIハーネスである。プロジェクトでは`.hermes/skills/`を優先スキル経路として使う。この場所は`skills/`のSSOTから同期されたミラーでなければならない。

Hermesはディレクトリを走査してスキルを見つけるため、登録用のmanifestや別のコマンドミラーは不要である。実際に読まれる表面だけを維持する。

確認項目意図
スキル `.hermes/skills/` ミラー
呼出し `/skill-name`
manifest 作らない
コマンドミラー 作らない
標準: skills SSOT → 同期 → Hermesミラー → スキル呼出し

信頼設定とコンテキスト予算は利用者が管理する

Hermesは利用者設定の信頼済みプロジェクトだけからスキルを自動読込する。これはプロンプト注入を防ぐ安全境界であり、リポジトリが迂回してはならない。

大きなAGENTS.mdは既定の長さ上限で静かに切られることがある。AGENTS.mdは薄いディスパッチャにし、詳細な規則はポインター先の文書へ置く。

確認項目意図
信頼は利用者所有。信頼は利用者所有。
AGENTS.mdは最小安全規則。AGENTS.mdは最小安全規則。
詳細は参照文書。詳細は参照文書。
切断警告を確認する。切断警告を確認する。
標準: 信頼済みプロジェクト → AGENTSポインター → 規則読込 → 実行

演習

大きなAGENTS.mdは既定の長さ上限で静かに切られることがある。AGENTS.mdは薄いディスパッチャにし、詳細な規則はポインター先の文書へ置く。

# User-side Hermes onboarding
hermes config set context_file_max_chars 100000

# Then add the project root to skills.trusted_project_dirs
# using the Hermes user configuration. Do not commit user configuration
# or bypass the trust control from the project repository.

HERMES.mdを作らない理由

HermesはHERMES.mdをAGENTS.mdより先に探す。ツインを作ると共通の指示を覆い隠し、二つの規則が時間とともにずれる。標準はHermesのAGENTS.md対応をそのまま使う。

同じ理由でミラーは独立した編集場所ではない。変更はSSOTで確認し、同期で配布する。

確認項目意図
HERMES.mdは作らない。HERMES.mdは作らない。
ミラーは配布コピー。ミラーは配布コピー。
AGENTS.mdはポインター。AGENTS.mdはポインター。
詳細規則は一か所に置く。詳細規則は一か所に置く。
標準: AGENTS.md → ポインター → 基準規則 → Hermes実行

ミラー、指示、安全境界を検証する

導入済みであることは安全な運用の証明ではない。ミラーの存在、除外対象の不在、AGENTS.mdのポインター、信頼とコンテキスト設定を確認する。

スキルが見つからないときは、モデルやプロンプトを変える前に信頼、ミラーの鮮度、コンテキスト読込を確認する。

確認項目意図
1. プロジェクトは信頼済みか。1. プロジェクトは信頼済みか。
2. ミラーは同期済みか。2. ミラーは同期済みか。
3. HERMES.mdが影を作らないか。3. HERMES.mdが影を作らないか。
4. 切断・同期失敗がないか。4. 切断・同期失敗がないか。
標準: 作成 → 信頼登録 → ミラー確認 → コンテキスト確認 → 監査証拠
