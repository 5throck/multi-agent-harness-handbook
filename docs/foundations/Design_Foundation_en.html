Core chapter

Design Foundation and UI Quality Gates

Learn operating practices that let a multi-agent team reuse and verify the same design decisions.

In this chapter
  • Design SSOT
  • Roles and handoffs
  • Component and screen contracts
  • Quality gates and evidence

Design SSOT

Record design tokens, component rules, screen states, and decision rationale in one design document. Align the source of a decision before implementation.

Roles and handoffs

Design defines rules and review criteria, implementation turns them into code, and QA independently checks the result.

Component and screen contracts

Specify component inputs, states, accessibility requirements, and loading, empty, and error states for standard screens as contracts.

Quality gates and evidence

UI changes must pass accessibility checks and preview review. Keep screenshots and review records so later agents and reviewers can trace the evidence.

Practice: Record the decision, assign an owner, and verify the result before the next pipeline stage.
