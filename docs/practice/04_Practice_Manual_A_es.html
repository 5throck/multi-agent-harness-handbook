1. Definición de subagentes

Claude App y Claude Code predefinen un único subagente utilizando un archivo Markdown colocado en la carpeta del proyecto. Claude App y Claude Code comparten los mismos archivos — ambos reconocen .claude/agents/*.md exactamente de la misma manera.

Claude App (Escritorio) .claude/agents/*.md

Colocar un archivo Markdown en la carpeta .claude/agents/ de la raíz del proyecto se reconoce automáticamente como un subagente personalizado en Claude App. El name se convierte en el identificador referenciado posteriormente como subagent_type. El mismo archivo funciona exactamente igual en Claude Code (CLI) — ambos comparten el mismo formato de definición de subagente.

---
name: reviewer
description: Revisa archivos de texto en busca de erratas
  y lagunas lógicas.
tools: Read, Grep
model: sonnet
---

Actúas como revisor. Lee el archivo dado
y presenta una lista de mejoras.

Claude Code (CLI) — Mismo .claude/agents/*.md que Claude App

Reconoce exactamente los mismos archivos .claude/agents/*.md escritos para Claude App, tal cual. No hay diferencia en cómo se definen los subagentes entre la aplicación de escritorio y el CLI.

Campo del frontmatterClaude App / Claude Code (.claude/agents)
name Obligatorio. Debe coincidir con el valor de subagent_type para ser invocable
description Describe cuándo se debe usar este agente; se referencia para decisiones de activación automática
tools Lista de herramientas disponibles; hereda el conjunto predeterminado si se omite
model Especifica un alias como sonnet / opus / haiku

2. Invocación/delegación a subagentes

Tanto Claude App como Claude Code invocan la herramienta Agent (también denominada herramienta Task en la documentación) para iniciar un subagente con su propio contexto separado.

Claude App (Escritorio) Herramienta Agent(Task)

En Claude App también, la sesión principal invoca la herramienta Agent (también denominada Task en la documentación) para iniciar un subagente con su propio contexto separado. Dado que el subagente no puede ver el historial de conversación de la sesión principal, el prompt debe contener de forma autosuficiente toda la información necesaria. Claude Code (CLI) utiliza exactamente la misma herramienta Agent/Task — cuando realiza una solicitud en lenguaje natural en la ventana de chat, se invoca internamente de forma similar a la que se muestra a continuación.

Agent(
  description   = "Revisar módulo de autenticación",
  prompt         = "Revisar la lógica de manejo de expiración
    de sesión en src/auth/login.ts y encontrar errores.",
  subagent_type  = "reviewer"
)

Claude Code (CLI) — Misma herramienta Agent(Task) que Claude App

Es exactamente el mismo método de invocación de la herramienta Agent/Task que Claude App. Realizar una solicitud en lenguaje natural en la terminal inicia un subagente de la misma manera.

3. Ejecución en paralelo

La familia Claude admite ejecución en paralelo de dos maneras.

Claude App (Escritorio) Equipos de agentes — en proceso

Activar la función experimental de equipos de agentes en Claude App permite que múltiples compañeros de equipo trabajen en paralelo. Sin embargo, la aplicación de escritorio solo admite teammateMode: in-process, y algunas navegaciones por teclado (como Shift+Abajo) están restringidas. Claude Code (CLI) también admite el mismo modo in-process, y adicionalmente el CLI permite elegir el modo tmux, que utiliza paneles divididos de tmux.

Ejecutar múltiples agentes simultáneamente en el mismo directorio o espacio de trabajo puede causar "superposición cognitiva" — un problema donde un agente confunde (alucina) los resultados de otro agente que trabaja en la misma carpeta como su propio contexto de trabajo. Separar agentes por directorio de trabajo o worktree es la práctica recomendada.

Claude Code (CLI) — Múltiples llamadas Agent en un mensaje

Cuando hay múltiples tareas independientes sin dependencias entre ellas, puede colocar múltiples llamadas Agent una al lado de la otra dentro de un solo mensaje para ejecutarlas concurrentemente. Claude Code despacha estas llamadas en paralelo.

Agent(description="Redactar documentación de API",
  prompt="...", subagent_type="writer")
Agent(description="Verificar cobertura de pruebas",
  prompt="...", subagent_type="reviewer")
ElementoClaude App (Escritorio)Claude Code (CLI)
Unidad de ejecución en paralelo Equipos de agentes (solo en proceso) Múltiples llamadas Agent en un mensaje / Equipos de agentes (en proceso + tmux)

4. Automatización/ganchos

En la familia Claude, la diferencia en automatización y ganchos radica entre App y Code.

Claude App (Escritorio) — Los ganchos no se activan

Incluso si define ganchos PostToolUse/TeammateIdle/TaskCompleted en .claude/settings.json, no se activan automáticamente en Claude App. Lo que el gancho habría hecho (por ejemplo, ejecutar un script de auditoría) debe ejecutarse manualmente después de que termine la sesión. En Claude Code (CLI), los ganchos del mismo archivo de configuración se activan automáticamente en respuesta a eventos — los equipos que necesiten una puerta de automatización deberían elegir razonablemente la interfaz de línea de comandos (CLI) en este punto.

Claude Code (CLI) — Los ganchos se activan automáticamente

Los ganchos PostToolUse/TeammateIdle/TaskCompleted en .claude/settings.json se ejecutan automáticamente en respuesta a eventos como guardados de archivos o finalización de tareas.

{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Write|Edit",
        "hooks": [{ "type": "command", "command": "bun scripts/audit.ts" }] }
    ]
  }
}
Los equipos de agentes es una función en rápida evolución — los nombres de indicadores, el comportamiento predeterminado y la composición de la interfaz pueden cambiar con cada versión, así que consulte las notas de la última versión antes de confiar en ella para un flujo de trabajo de producción.
