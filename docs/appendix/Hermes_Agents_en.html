Appendix

Hermes Agents

Hermes Agent (NousResearch/hermes-agent) is a model-agnostic, open-source agent harness, supported as the workspace's fifth platform since 2026-09-25. The workshop exercises still use four tools (Claude Code, Claude Desktop App, Antigravity, Antigravity CLI); this appendix summarizes what projects that use Hermes need to know.

Scope

Under ADR-0088 the platform directories grew from .claude/, .gemini/, .agents/, and .codex/ to five with .hermes/. The addition is strictly additive: existing platform skills and validators behave as before. The PM Gateway and shared governance still apply; Hermes is one more platform that executes them.

The Hermes.md instruction file

ADR-0093 added Hermes.md at L0, L1, and every L2 variant. It belongs to the CLAUDE.md/GEMINI.md/CODEX.md family of platform-specific behavioral instructions and is not a copy of AGENTS.md. Hermes loads exactly one context file with a 20,000-character default cap, so Hermes.md stays under 19,000 characters at every layer and links out for detail.

Skill mirror and invocation

Hermes skills are a mirror of the SSOT skills/, written to .hermes/skills/ by scripts/sync-skills.ts. Hermes is never pointed at skills/ directly, so security-gate exclusions and country/variant pruning stay on one code path. Hermes invokes skills natively as /<skill-name>, so there is no commands mirror; because it is model-agnostic, agent tier: settings and the model registry are unchanged.

Safe operation

Project skills auto-load only for project roots listed in Hermes' trusted_project_dirs. This is Hermes' prompt-injection defense, so never bypass it; the user registers trusted roots. Start with minimal permissions and route write or externally visible work through approval and QA gates.

AGENTS.md as a thin dispatcher

Hermes' 20,000-character cap exposed that AGENTS.md was being truncated, so ADR-0090 turned AGENTS.md at every layer into a thin dispatcher of at most 15,000 characters. AGENTS.md keeps a pointer table and summaries; operational detail such as the PM Gateway phase protocol and execution plan templates moved to files under docs/governance/agents/. CONSTITUTION.md remains the rules SSOT.

The co-workspace service

ADR-0092 introduced an L0 service (first named team-gateway, now services/co-workspace/) that serves variant agent teams over the web. Each tenant gets a project scaffolded with new-project.ts --platform hermes and runs headless Hermes with its own HERMES_HOME. Variants are exposed as models over OpenAI- and Anthropic-compatible APIs. The service is workspace-only and is never shipped to scaffolded projects.

Other changes in the same period

A new-project skill now lets you scaffold variant projects from L0 as a skill (running the script directly still works). A new root agent, skill-graph-analyst, handles skill-graph analytics. ADR-0091 made the co-newbiz model the standard for the four-layer KR profile and project LLM configuration (<PROJ>_LLM_* environment variables). The /meeting command was retired on 2026-09-26; use the meeting-facilitation skill instead.

Verification and sync

For existing projects, upgrade-project delivers the COMMON-HERMES managed zone by MERGE so they receive Hermes.md. New projects are scaffolded with --platform hermes or all. Use bun scripts/audit.ts to confirm each platform follows the same governance, PR, and verification rules.
