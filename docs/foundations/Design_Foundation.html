디자인 SSOT

디자인 토큰, 컴포넌트 규칙, 화면 상태와 결정 근거를 하나의 설계 문서에 기록합니다. 구현물보다 결정의 출처를 먼저 맞춥니다.

역할과 핸드오프

디자인 담당은 규칙과 검수 기준을 정의하고, 구현 담당은 이를 코드로 옮기며, QA 담당은 독립적으로 결과를 확인합니다.

컴포넌트·화면 계약

컴포넌트의 입력, 상태, 접근성 요구사항과 표준 화면의 로딩·빈·오류 상태를 계약으로 명시합니다.

품질 게이트와 증거

UI 변경은 접근성 검사와 프리뷰 확인을 통과해야 합니다. 스크린샷·검수 기록을 남겨 다음 에이전트와 리뷰어가 판단 근거를 추적하게 합니다.
