Hermes Agents

Hermes Agent(NousResearch/hermes-agent)는 특정 모델에 묶이지 않는 오픈소스 에이전트 하네스로, 2026-09-25부터 워크스페이스의 다섯 번째 플랫폼으로 지원됩니다. 워크숍 실습은 여전히 Claude Code·Claude Desktop App·Antigravity·Antigravity CLI 네 도구로 진행하며, 이 부록은 Hermes를 쓰는 프로젝트가 알아야 할 구조를 정리합니다.

적용 범위

ADR-0088에 따라 플랫폼 디렉터리는 .claude/·.gemini/·.agents/·.codex/에 .hermes/가 더해져 다섯 개가 되었습니다. 추가는 순수하게 덧붙이는 방식이라 기존 플랫폼의 스킬·검증 동작은 바뀌지 않습니다. PM Gateway와 공통 거버넌스는 그대로 적용되고, Hermes는 그것을 실행하는 플랫폼 중 하나입니다.

Hermes.md 지시 파일

ADR-0093으로 L0·L1과 모든 L2 variant에 Hermes.md가 생겼습니다. CLAUDE.md·GEMINI.md·CODEX.md와 같은 계열의 플랫폼 전용 행동 지침이며, AGENTS.md를 복사한 파일이 아닙니다. Hermes는 컨텍스트 파일을 하나만 읽고 기본 한도가 20,000자이므로, Hermes.md는 모든 계층에서 19,000자 미만으로 유지하고 세부 내용은 포인터로 연결합니다.

스킬 미러와 호출

Hermes 스킬은 SSOT인 skills/를 scripts/sync-skills.ts가 .hermes/skills/로 미러링한 것입니다. Hermes가 skills/를 직접 가리키게 하지 않는 이유는 보안 게이트 제외와 국가·variant 범위 가지치기를 한 경로에서 관리하기 위해서입니다. Hermes는 스킬을 /<skill-name>으로 직접 호출하므로 커맨드 미러는 없으며, 모델에 묶이지 않으므로 에이전트의 tier: 설정과 모델 레지스트리도 바뀌지 않습니다.

안전한 운영

프로젝트 스킬은 Hermes 설정의 trusted_project_dirs에 등록된 프로젝트 루트에서만 자동으로 로드됩니다. 이것은 프롬프트 주입을 막는 Hermes의 방어선이므로 우회하지 말고 사용자가 직접 등록합니다. 권한은 최소로 시작하고, 쓰기·외부 영향 작업은 승인과 QA 게이트를 거칩니다.

AGENTS.md 얇은 디스패처

Hermes의 20,000자 한도 때문에 AGENTS.md가 잘리는 문제가 드러나면서, ADR-0090은 모든 계층의 AGENTS.md를 15,000자 이하의 얇은 디스패처로 바꾸었습니다. AGENTS.md에는 포인터 표와 요약만 남고, PM Gateway 단계 절차와 실행 계획 템플릿 같은 운영 세부는 docs/governance/agents/ 아래 파일로 옮겨졌습니다. 규칙의 SSOT는 여전히 CONSTITUTION.md입니다.

co-workspace 서비스

ADR-0092는 variant 에이전트 팀을 웹에서 쓸 수 있게 하는 L0 서비스(처음 이름 team-gateway, 지금은 services/co-workspace/)를 도입했습니다. 테넌트마다 new-project.ts --platform hermes로 프로젝트를 만들고, 헤드리스 Hermes를 테넌트별 HERMES_HOME으로 실행합니다. OpenAI·Anthropic 호환 API로 variant를 모델처럼 노출하며, 스캐폴딩된 프로젝트에는 배포되지 않는 워크스페이스 전용 구성 요소입니다.

함께 바뀐 것들

같은 시기에 다음도 바뀌었습니다. new-project 스킬이 추가되어 variant 프로젝트 스캐폴딩을 L0에서 스킬로 호출할 수 있습니다(스크립트 직접 실행도 그대로 가능). 루트 에이전트에 스킬 그래프 분석을 맡는 skill-graph-analyst가 더해졌습니다. ADR-0091은 co-newbiz 방식을 KR 프로필(4계층)과 프로젝트 LLM 설정(<PROJ>_LLM_* 환경 변수)의 표준으로 정했습니다. /meeting 커맨드는 2026-09-26에 폐지되었고 meeting-facilitation 스킬로 대체됩니다.

검증과 동기화

기존 프로젝트에는 upgrade-project가 COMMON-HERMES 관리 영역을 MERGE 방식으로 전달해 Hermes.md를 받게 합니다. 새 프로젝트는 --platform hermes 또는 all로 스캐폴딩하면 됩니다. 플랫폼별 결과가 같은 거버넌스·PR·검증 규칙을 지키는지 bun scripts/audit.ts로 확인합니다.
