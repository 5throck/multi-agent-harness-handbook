5장 · i18n 설계와 콘텐츠 품질

번역 파일을 늘리는 작업이 아니라, 언어·국가·형식·화면 상태가 함께 유지되는 제품 계약으로 i18n을 설계한다.

이 장에서 다루는 것
  • locale과 국가 프로필 구분
  • 번역 가능한 자산과 SSOT
  • 길이·형식·상태를 고려한 화면
  • 동등성 검증과 운영 실습

i18n은 언어 선택 기능보다 넓다

국제화(i18n)는 여러 언어와 지역에서 같은 제품 과업을 완수하도록 설계하는 일이다. 언어(locale)는 문장, 날짜, 숫자, 정렬 방식에 영향을 준다. 국가 프로필은 법규, 통화, 데이터 출처, 공개 범위처럼 지역별 업무 규칙에 영향을 준다. 둘을 같은 설정으로 취급하면 번역을 바꾼 일이 업무 규칙까지 바꾸는 위험이 생긴다.

여행 가방에 비유하면 locale은 안내문을 읽는 언어와 현지 표기법이고, 국가 프로필은 반입 규칙과 사용할 화폐다. 둘은 함께 선택될 수 있지만 각각의 변경 책임과 검증 방법이 다르다.

검토 항목의도
locale UI 문구, 날짜·시간, 숫자·통화 표기
country profile 법규, 데이터 제공자, 권한·공개 범위
콘텐츠 사람이 읽는 문장과 대체 텍스트
식별자 파일명, 키, 코드, URL은 번역하지 않는다.
표준: 사용자 선택 → locale 문구·형식 적용 / country profile 업무 규칙 적용

문구와 구조의 단일 출처를 만든다

번역을 화면 파일에 직접 흩어 두면 한 언어에서만 버튼, 오류 문구, 도움말, 빈 상태가 빠지기 쉽다. 기준 언어를 콘텐츠의 단일 출처(SSOT)로 정하고, 메시지 키·화면 구조·상태 목록·용어집을 함께 관리한다. 번역은 기준 구조를 복사한 뒤 보이는 문장을 옮기는 작업이어야 한다.

키는 개발자 편의를 위한 암호가 아니라 의미를 가진 계약이다. `review.approve`처럼 기능과 행동이 드러나는 키를 쓰고, 같은 키를 다른 의미로 재활용하지 않는다. 코드·URL·기술 식별자는 그대로 두어 실행 가능한 문서를 보존한다.

검토 항목의도
기준 언어 제목·헤딩·목록·코드 블록 수의 기준
메시지 키 의미가 안정된 이름
용어집 한 개념에 한 표현
변경 기록 문구 변경과 화면 구조 변경을 구분
표준: 기준 콘텐츠 → 메시지 키·용어집 → 번역본 → 구조·링크·용어 검사

실습

키는 개발자 편의를 위한 암호가 아니라 의미를 가진 계약이다. `review.approve`처럼 기능과 행동이 드러나는 키를 쓰고, 같은 키를 다른 의미로 재활용하지 않는다. 코드·URL·기술 식별자는 그대로 두어 실행 가능한 문서를 보존한다.

{
  "review": {
    "approve": "승인",
    "returnForChanges": "수정 요청",
    "empty": "검토할 보고서가 없습니다."
  },
  "errors": {
    "network": "연결을 확인한 뒤 다시 시도하세요."
  }
}

긴 번역문과 지역 형식을 화면의 입력으로 취급한다

영어 한 단어가 독일어·스페인어·일본어에서는 더 길거나 짧을 수 있다. 버튼과 표의 너비를 고정하면 번역된 문장이 잘리거나 화면 밖으로 밀려난다. 날짜와 숫자는 문자열을 이어 붙이지 말고 locale 형식기로 만들며, 줄바꿈과 읽는 순서는 실제 언어판에서 확인한다.

빈 상태와 오류 상태도 번역 대상이다. 성공한 기본 화면만 번역하면 사용자는 문제가 생겼을 때 다른 언어로 된 해결 방법을 보게 된다. 긴 이름, 0개 결과, 권한 거부, 네트워크 실패를 각 언어에서 미리 본다.

고정 폭 대신 유연한 레이아웃을 사용한다.고정 폭 대신 유연한 레이아웃을 사용한다.
통화·날짜·복수형은 locale 형식기를 사용한다.통화·날짜·복수형은 locale 형식기를 사용한다.
텍스트가 늘어나는 버튼과 표를 실제 언어로 점검한다.텍스트가 늘어나는 버튼과 표를 실제 언어로 점검한다.
오류 해결 행동과 대체 텍스트도 번역한다.오류 해결 행동과 대체 텍스트도 번역한다.
표준: 메시지·형식 데이터 → 유연한 컴포넌트 → 상태별 렌더링 → 언어별 미리 보기

동등성은 문장 수가 아니라 사용자 과업으로 검증한다

번역이 자연스러워도 한 언어에서 저장 버튼, 경고, 링크, 실습 단계가 빠지면 제품은 동등하지 않다. 자동 검사는 헤딩·코드 블록·내부 링크·검색 색인을 비교하고, 사람 검토는 용어·문체·잘림·국가 규칙을 확인한다. 두 검사는 서로 대체하지 않는다.

변경은 기준 언어에서 먼저 확정하고 같은 변경 집합에 모든 언어판을 넣는다. 한 언어만 급히 수정해야 한다면 후속 작업과 위험을 기록한다. 배포 전에는 언어 전환, 빈·오류 상태, 날짜·통화 형식, 접근성 이름을 직접 확인한다.

검토 항목의도
1. 기준 언어와 번역본의 헤딩·실습·링크가 같은가?1. 기준 언어와 번역본의 헤딩·실습·링크가 같은가?
