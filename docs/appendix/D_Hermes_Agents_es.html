Apéndice D · Operaciones de Hermes Agents

Usa Hermes Agent dentro de la gobernanza existente sin crear una segunda fuente de instrucciones.

En este capítulo

  • Trust and context budget

Comprende la superficie de plataforma de Hermes

Hermes Agent es un arnés CLI independiente del proveedor. Un proyecto usa .hermes/skills/ como ruta primaria de habilidades. Debe ser un espejo sincronizado de skills/, no un atajo directo que evada exclusiones de seguridad o alcance de país y variante.

Hermes descubre habilidades por directorios y las invoca con /skill-name; no necesita manifest ni espejo adicional de comandos.

ElementoIntención
Habilidades espejo .hermes/skills/
Invocación /skill-name
Manifest no crear
Espejo de comandos no crear
Estándar: SSOT skills → sincronización → espejo Hermes → invocación

El usuario administra confianza y presupuesto de contexto

Hermes carga habilidades del proyecto solo si la raíz está en skills.trusted_project_dirs del usuario. Es una defensa contra inyección de prompts y el repositorio no debe saltarla.

Un AGENTS.md grande puede truncarse de forma silenciosa. Mantén un dispatcher ligero con punteros y coloca la política detallada en documentos referenciados.

ElementoIntención
La confianza pertenece al usuario.Muestra que el límite de confianza frente a la inyección de prompts lo controla el usuario, no el repositorio.
AGENTS.md entrega reglas mínimas.Para cargar solo las reglas esenciales dentro del presupuesto de contexto.
La política detallada vive fuera.Para cargar las reglas profundas solo cuando se necesiten, evitando truncamiento y coste.
Revisa avisos de truncamiento.Para detectar antes de entregar el mal funcionamiento silencioso de un AGENTS.md truncado.
Estándar: Proyecto confiable → punteros de AGENTS → política → ejecución

Práctica

Un AGENTS.md grande puede truncarse de forma silenciosa. Mantén un dispatcher ligero con punteros y coloca la política detallada en documentos referenciados.

# User-side Hermes onboarding
hermes config set context_file_max_chars 100000

# Then add the project root to skills.trusted_project_dirs
# using the Hermes user configuration. Do not commit user configuration
# or bypass the trust control from the project repository.

Por qué no se crea HERMES.md

Hermes busca HERMES.md antes de AGENTS.md. Un archivo gemelo ocultaría la fuente compartida de instrucciones y generaría divergencia. El estándar usa directamente la compatibilidad nativa con AGENTS.md.

El espejo de habilidades tampoco es un lugar de edición independiente. Revisa cambios en el SSOT y publícalos con sincronización.

ElementoIntención
No crear HERMES.md.Para que no oculte AGENTS.md.
El espejo es copia de despliegue.Las ediciones ocurren en el SSOT.
AGENTS.md es dispatcher ligero.Para ahorrar contexto con un despachador delgado.
La política detallada tiene una fuente.Para mantener una única fuente de verdad.
Estándar: AGENTS.md → punteros → política canónica → ejecución

Verifica espejo, instrucciones y límites de seguridad

La instalación no prueba operación segura. Confirma el espejo, las exclusiones, los punteros de AGENTS.md y la configuración de confianza y contexto.

Si falta una habilidad, revisa confianza, frescura del espejo y carga de contexto antes de cambiar prompts o modelos.

ElementoIntención
1. ¿La raíz es confiable?Para verificar primero la precondition de la carga automática de habilidades.
2. ¿El espejo está sincronizado?Para evitar que un espejo obsoleto ejecute habilidades desactualizadas.
3. ¿HERMES.md no oculta AGENTS.md?Para conservar una única fuente de verdad del archivo de instrucciones.
4. ¿No hay errores de truncamiento ni sincronización?Para cerrar la aceptación en un estado limpio y sin avisos.
Estándar: Scaffold → confianza → espejo → contexto → habilidad → evidencia
Autoevaluación
  1. ¿Cuándo se actualiza el espejo .hermes/skills y qué comprobación confirma la sincronización?
  2. ¿Por qué no debe crearse HERMES.md?
  3. ¿Quién posee la configuración de confianza (skills.trusted_project_dirs) y por qué el repositorio no debe cambiarla?
  4. Si aparece un aviso de truncamiento de contexto, ¿qué hay que hacer antes de entregar?

Procedimiento de configuración y comandos de verificación

El repositorio nunca modifica la configuración de confianza del usuario. Confía explícitamente en la raíz del proyecto en Hermes y luego verifica el espejo sincronizado .hermes/skills/ y un AGENTS.md ligero.

# User-owned configuration
hermes config set context_file_max_chars 100000
# Add the project root to skills.trusted_project_dirs in user configuration.
# Do not commit user configuration or create HERMES.md.

Solución de problemas: comprueba el orden de carga antes que los síntomas

Si no aparecen skills, revisa la ruta de confianza y el espejo. Si faltan reglas, revisa el tamaño y los enlaces de AGENTS.md. Si hay conflicto, comprueba primero HERMES.md.

SymptomFirst check
Skill unavailabletrusted_project_dirs and .hermes/skills mirror
Rule missingthin AGENTS.md and its pointer targets
Conflicting instructionremove HERMES.md; retain AGENTS.md as SSOT
