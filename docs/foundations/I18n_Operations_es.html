Diseño de i18n y Calidad de Contenido

Diseña i18n como un contrato de producto para idioma, reglas de país, formatos y estados de pantalla.

i18n es más amplio que un selector de idioma

La internacionalización permite completar la misma tarea en varios idiomas y regiones. Un locale afecta texto, fechas, números y orden. Un perfil de país afecta regulación, moneda, proveedores de datos y divulgación. Mezclarlos permite que un cambio de texto modifique una regla de negocio.

Como en un viaje, el locale es el idioma y la notación de una guía; el perfil de país es la regla fronteriza y la moneda. Pueden elegirse juntos, pero tienen responsables y validaciones diferentes.

Crea una única fuente de verdad para texto y estructura

Cuando las traducciones están dispersas en las pantallas, un idioma puede perder un botón, un error, ayuda o un estado vacío. Mantén un idioma canónico y administra claves, estructura, estados y glosario juntos. Una traducción debe copiar la estructura y traducir solo el lenguaje visible.

Una clave es un contrato semántico. Usa nombres como `review.approve` y no reutilices una clave con otro significado.

Práctica

Una clave es un contrato semántico. Usa nombres como `review.approve` y no reutilices una clave con otro significado.

{
  "review": {
    "approve": "승인",
    "returnForChanges": "수정 요청",
    "empty": "검토할 보고서가 없습니다."
  },
  "errors": {
    "network": "연결을 확인한 뒤 다시 시도하세요."
  }
}

Considera la longitud y el formato regional como entradas de diseño

Las palabras se expanden o reducen entre idiomas. Los anchos fijos recortan texto o expulsan contenido. Formatea fechas y números con herramientas conscientes del locale y prueba saltos de línea en la edición real.

Los estados vacíos y de error también requieren traducción. Previsualiza nombres largos, cero resultados, denegación de permisos y fallos de red.

Valida la paridad por tarea de usuario

Una prosa natural no basta si una edición pierde guardar, una advertencia, un enlace o un paso de ejercicio. La automatización compara encabezados, bloques de código, enlaces y búsqueda; la revisión humana comprueba terminología, tono, recortes y reglas de país.

Finaliza primero el idioma canónico y cambia todas las ediciones juntas. Antes de entregar, prueba cambio de idioma, estados vacíos y de error, formatos y nombres accesibles.
