Capítulo 4 §2-B · Práctica de equipos multiagente

Una guía práctica que comienza desde una carpeta de práctica vacía y avanza a través de escenarios centrados en Antigravity (Escritorio)/Antigravity CLI — la guía se presenta primero desde la perspectiva de la aplicación de escritorio, seguida del equivalente en CLI  |  ← Volver al documento de referencia del Cap.4 §1

Versión/ámbito objetivoAntigravity CLI (agy) 1.1.0+, Antigravity 2.0 — centrado en Antigravity; para el equivalente de Claude App/Code consulte el Cap.4 §2-A
Propósito de este archivoPráctica práctica de 4 etapas que cubre definición/invocación de subagentes, canalizaciones secuenciales, composición dinámica de equipo/combinación de flujos de trabajo y ejecución en paralelo, centrada en Antigravity (Escritorio)/Antigravity CLI

El principio detrás de todo el curso — si se aprende la práctica alrededor de una sola herramienta, tendrá que reaprender todo desde cero al cambiar a otra. Por eso, cada escenario a continuación primero escribe el rol del subagente como una especificación AGENTS.md neutral a la herramienta, y luego la "implementa" como un objetivo en lenguaje natural en la familia Antigravity (consulte Cap.2 §5 AGENTS.md). El enfoque correspondiente en la familia Claude se cubre en Cap.4 §2-A. Confirmar en la práctica que existe una única definición pero el método de ejecución difiere según la herramienta es el objetivo central de esta práctica.

Configuración: instalación de los programas necesarios

La práctica a continuación se centra en Antigravity (Escritorio) y Antigravity CLI (agy). Si su entorno local aún no tiene estas herramientas, la automatización de configuración del entorno incluida con este manual — la guía de configuración — instalará automáticamente exactamente lo que necesitan los ejercicios de este capítulo. Siga las instrucciones para descargar y ejecutar el script localmente.

📦 Antes de instalar — Cosas que verificar

Antes de ejecutar el script, lea primero la lista de verificación previa a la instalación. Este documento enumera los siguientes requisitos previos.

  • Una cuenta de Google para usar Antigravity (debe ser un plan basado en suscripción/cuenta, no una clave API individual)
  • Una cuenta de GitHub que pueda completar gh auth login
  • Al menos 5 GB de espacio libre en disco
  • Privilegios de administrador o sudo
Si aún no tiene una cuenta de GitHub
① Vaya a github.com/signup en su navegador.
② Ingrese su dirección de correo electrónico, contraseña y nombre de usuario — el nombre de usuario se usará tal cual en la URL del repositorio (github.com/<nombredeusuario>/...), así que elíjalo con cuidado.
③ Complete el rompecabezas/verificación de código para evitar registros automatizados.
④ Abra el correo de verificación enviado a la dirección con la que se registró y complete la verificación de correo electrónico — omitir este paso puede bloquear más tarde gh auth login o la creación de repositorios.
⑤ Registrarse en el plan gratuito es suficiente — los ejercicios de práctica/PR de este manual no requieren un plan de pago.
Una vez completado el registro, el GitHub CLI (gh) se instala junto con el script de configuración anterior, y conecta su terminal a esa cuenta con el comando gh auth login a continuación. 
gh auth login
# Siga los prompts: elija GitHub.com → HTTPS → Iniciar sesión con un navegador web (recomendado)
# Cuando el navegador se abra, inicie sesión con la cuenta que acaba de crear y confirme el código de autenticación

Instalación en Windows

Dado que la notación de rutas de este manual está basada en Windows, los usuarios de Windows deben descargar setup-windows.ps1, colocarlo en una carpeta de práctica dedicada (por ejemplo, harness-lab/setup/), abrir PowerShell como administrador y ejecutar el siguiente comando.

Cómo abrir PowerShell como administrador
① Abra el menú Inicio y busque PowerShell.
② Haga clic derecho en "Windows PowerShell" en los resultados de búsqueda.
③ Seleccione "Ejecutar como administrador" en el menú que aparece.
④ Cuando aparezca el aviso de Control de cuentas de usuario (UAC), haga clic en "Sí" para aprobar.
Si la barra de título muestra algo como Administrador: Windows PowerShell con "Administrador" adjunto, se abrió correctamente. Algunos pasos, como la instalación de winget, pueden generar errores u omitirse silenciosamente sin privilegios de administrador. 
cd ./setup
.\setup-windows.ps1
# Indicadores opcionales: -WSL2, -WezTerm, -Docker, -Force (reinstalar también las herramientas ya instaladas)

Después de que el script termine, cierre y vuelva a abrir completamente su terminal para que los cambios en PATH surtan efecto.

Instalación en macOS / Linux

En macOS, descargue y use setup-mac.sh; en Linux, use setup-linux.sh. Ambos admiten los indicadores opcionales --wezterm y --docker.

# macOS
cd ./setup && bash setup-mac.sh

# Linux
cd ./setup && bash setup-linux.sh

Verificación de la instalación

Independientemente del sistema operativo, ejecutar setup-common.ts con bun imprime una tabla de verificación que muestra el estado de su instalación. Si cada elemento muestra ✅, está listo para continuar con la práctica a continuación.

cd ./setup && bun setup-common.ts

Entre las herramientas que este proyecto instala, las directamente relevantes para la práctica de este capítulo son: Antigravity (Escritorio), agy (CLI de Antigravity), y también gh (GitHub CLI), que se utiliza en capítulos posteriores.

El CLI de Antigravity (agy) es un solo binario compilado que no requiere instalación de runtime separada — simplemente descomprímalo y colóquelo en el PATH para ejecutarlo inmediatamente. Orientaciones anteriores que aún circulan, como "instalar la interfaz de línea de comandos (CLI) de Gemini globalmente a través de npm", ya no son válidas. Consulte el método de instalación más reciente en antigravity.google/docs/cli/getting-started.
Si ocurre un problema durante la instalación, los registros se guardan en la carpeta %USERPROFILE%\workshop-setup-logs\ en Windows. Verifique estos registros primero al solucionar problemas.
● Principiante Primeros pasos El primer paso: dar un objetivo en Antigravity (Escritorio) y observar la generación dinámica
G-1 Principiante Crear y llamar a tu primer subagente personalizado
Un desarrollador que prueba el arnés por primera vez crea una nueva carpeta de práctica vacía, harness-lab/, primero escribe el rol reviewer como una especificación AGENTS.md neutral a la herramienta, y luego lo "implementa" como un objetivo en lenguaje natural en Antigravity (Escritorio) para invocarlo. Dado que esta carpeta está dedicada a la práctica, no se mezclará con otros archivos del proyecto.
Elementos utilizados
AGENTS.md (Cap.2) Definición de un subagente Invocación de un subagente
Paso a paso
  1. ① Crear y entrar en la carpeta de práctica

    Cree una nueva carpeta harness-lab debajo de la carpeta actual y muévase a ella. Ejecute todos los comandos posteriores dentro de esta carpeta.

    mkdir -p harness-lab
cd harness-lab
  2. ② Escribir la especificación de rol común — AGENTS.md

    Escriba el rol reviewer como texto plano, libre de expresiones específicas de herramientas, para que se lea con el mismo significado ya sea en Claude, Antigravity o cualquier otra herramienta que admita el estándar AGENTS.md. Este único archivo se convierte en la única fuente de verdad de "qué hace este rol," y Antigravity a continuación simplemente implementa esta fuente como un objetivo en lenguaje natural. En macOS/Linux/Git Bash, use el comando tal cual.

    cat > AGENTS.md << 'EOF'
## Agent: reviewer

Role: Review text files for typos, logical gaps, and areas for improvement.
Input: Path to the text file to review
Output: A list of typos, logical gaps, and improvement points
Permissions: Read-only — does not modify the file directly.
EOF

    En Windows PowerShell, el comando cat en sí es un alias para Get-Content y puede usarse tal cual para leer archivos. Sin embargo, la sintaxis heredoc para ingresar múltiples líneas directamente, como << 'EOF', no es compatible, así que escriba el mismo contenido como una cadena here-string entre comillas (@'...'@) y escríbalo en el archivo con Set-Content.

    @'
## Agent: reviewer

Role: Review text files for typos, logical gaps, and areas for improvement.
Input: Path to the text file to review
Output: A list of typos, logical gaps, and improvement points
Permissions: Read-only — does not modify the file directly.
'@ | Set-Content AGENTS.md
Antigravity (Escritorio) — Implementar la misma especificación AGENTS.md como un objetivo en lenguaje natural

Antigravity no tiene concepto de archivos predefinidos como .claude/agents. En su lugar, mantenga el AGENTS.md que acaba de escribir en el espacio de trabajo tal cual, y proporcione la misma especificación en su objetivo.

  1. ① Preparar el archivo a revisar de antemano (terminal) 
    echo "This project is very good. This is really great." > notes.txt
  2. ② Crear un Espacio de trabajo en el Administrador de agentes de Antigravity

    Abra el Administrador de agentes y cree un nuevo Espacio de trabajo apuntando a la carpeta harness-lab/ (que ya contiene AGENTS.md).

  3. ③ Dar el objetivo — Pegue la oración a continuación en el chat del Espacio de trabajo y envíela 
    Review notes.txt according to the reviewer role spec written in AGENTS.md.
    El agente que maneja el Espacio de trabajo lee AGENTS.md, toma la especificación de rol/entrada/salida/permisos como su objetivo y decide por sí mismo las tareas necesarias (leer el archivo, compilar puntos de mejora). Dado que AGENTS.md es la única fuente de verdad de "qué criterios usar para la revisión," los criterios de revisión (erratas, lagunas lógicas, puntos de mejora) se determinan por esta especificación.

El CLI de Antigravity (agy) también permite practicar el mismo concepto — proporcione solo el objetivo a través de /goal, sin archivo predefinido.

cd harness-lab && agy
/goal Review the notes.txt file and summarize the improvement points
Dado que Antigravity no tiene archivo de definición, no se pueden restringir los permisos de antemano con un campo tools como en la familia Claude. En su lugar, es más seguro acotar claramente el propio objetivo, como "solo leer y resumir." La especificación Permissions: Read-only escrita en AGENTS.md también sirve para comunicar el límite de permisos al orquestador.
● Intermedio Flujo de trabajo diario Un patrón práctico donde la sesión principal actúa como orquestador dirigiendo a dos agentes especialistas, escritor y revisor, en secuencia
D-1 Intermedio Canalización de dos etapas escritor → revisor
Un practicante que ha terminado G-1 primero especifica un segundo rol, writer, en la misma carpeta harness-lab/, en AGENTS.md de la misma manera que en G-1, y luego lo implementa en Antigravity (Escritorio) como un objetivo en lenguaje natural. Se hace que el orquestador mantenga el orden en una canalización donde escritor redacta primero y revisor critica el resultado.
Elementos utilizados
AGENTS.md (Cap.2) Definición de un subagente Invocación de un subagente
Paso a paso
  1. Agregar la especificación de rol común — Añadir la entrada de escritor a AGENTS.md

    Continúe escribiendo el rol writer en el mismo AGENTS.md creado en G-1. Deje la entrada de revisor tal cual y agregue solo el contenido a continuación. En macOS/Linux/Git Bash, use el comando tal cual.

    cat >> AGENTS.md << 'EOF'

## Agent: writer

Role: Write a short 3–5 sentence draft on a given topic.
Input: Topic, path to save the file
Output: A draft text file
Permissions: Write allowed — saves only to the specified file.
handoff_to: reviewer (proceeds to review once the draft is complete)
EOF

    En Windows PowerShell, agregue la cadena here-string con Add-Content (debe usar Add-Content, ya que Set-Content sobrescribe el archivo y borraría la entrada de revisor).

    @'

## Agent: writer

Role: Write a short 3–5 sentence draft on a given topic.
Input: Topic, path to save the file
Output: A draft text file
Permissions: Write allowed — saves only to the specified file.
handoff_to: reviewer (proceeds to review once the draft is complete)
'@ | Add-Content AGENTS.md
Antigravity (Escritorio) — El orquestador descompone dos especificaciones AGENTS.md en un solo objetivo por sí mismo

Antigravity no divide writer/reviewer en archivos predefinidos separados de antemano. En su lugar, simplemente haga referencia a las dos especificaciones de rol ya escritas en AGENTS.md (revisor en G-1, escritor ahora). Continúe en el chat del mismo Espacio de trabajo creado en G-1.

  1. ① Dar el objetivo de dos etapas — Pegue la oración a continuación en el chat del Espacio de trabajo y envíela 
    Following the writer spec in AGENTS.md, first write a draft in draft.txt on the topic 'The advantages of remote work', and once it's done, review that draft following the reviewer spec in AGENTS.md. Proceed through the two stages in order.
    El orquestador lee la relación handoff_to: reviewer en AGENTS.md y divide el objetivo por sí mismo en dos subtareas, "escribir borrador → revisar," iniciando la tarea de revisión solo después de que la redacción del borrador esté completa. El punto distintivo es que la responsabilidad de la secuencia recae dentro del orquestador, no en el usuario — aunque "qué criterios usar para la revisión" sigue teniendo a AGENTS.md como única fuente de verdad.

El CLI de Antigravity (agy) también permite dar el mismo objetivo de una vez. Ponga toda la canalización en una sola oración con /goal y el orquestador la descompondrá por sí mismo; si es necesario, también puede delegar la etapa de revisión al fondo con /agent y continuar con otro trabajo.

agy
/goal First write a draft in draft.txt on the topic 'The advantages of remote work',
then once it's done, review that draft and summarize the improvement points
D-2 Intermedio Observar cómo cambia la composición del equipo y el flujo de trabajo según la solicitud
Este escenario permite ver de primera mano la "composición dinámica del equipo" y las "combinaciones de flujos de trabajo diversos" cubiertas en Cap.2 §4b. Deje las dos especificaciones de rol writer y reviewer creadas en D-1 tal cual, y varíe solo la naturaleza de la solicitud para observar exactamente qué tareas realiza realmente el orquestador, cuántas veces y en qué orden — el punto clave es que nunca se crea una nueva definición de subagente.
Elementos utilizados
Composición dinámica del equipo y flujos de trabajo diversos
Antigravity (Escritorio) — La misma flexibilidad se manifiesta incluso solo con objetivos en lenguaje natural

Dado que Antigravity genera subagentes dinámicamente desde el principio, esta flexibilidad se manifiesta más directamente. Continúe en el mismo chat del Espacio de trabajo usado en D-1.

  1. ① Una instrucción de objetivo simple 
    Just skim draft.txt for typos.
    El orquestador juzga que esta solicitud no necesita un rol de escritura y ensambla solo un rol de revisión sobre la marcha. Este es el ejemplo más simple que muestra que, aunque ambos roles están definidos en AGENTS.md, la composición real desplegada la decide el orquestador cada vez, por solicitud.
  2. ② Una instrucción de objetivo compuesta 
    Write a new draft in draft2.txt on the topic 'The four-day workweek' first, and once it's done, review that draft independently and simultaneously from both a grammar perspective and a logic perspective.
    El orquestador ensambló solo un rol de revisión sobre la marcha en ①, y en ② ensambla un nuevo equipo con un rol de escritura y dos roles de revisión (con perspectivas diferentes). Dado que no hay archivos de subagente predefinidos en absoluto, el principio "ensamblar un nuevo equipo adecuado para esta tarea cada vez" se destaca más claramente.
Comparar ① y ② lado a lado deja claro que "qué roles están definidos en AGENTS.md" y "qué composición se despliega realmente para esta tarea" son capas diferentes. La primera se fija de antemano en AGENTS.md, pero la segunda la decide el orquestador de nuevo con cada solicitud.
Ver también: Cap.2 §4b — Composición dinámica del equipo y flujos de trabajo diversos, Cap.4 §1 Referencia — Ejecución en paralelo
● Avanzado Usuario avanzado Operación en paralelo ejecutando escritor y revisor simultáneamente contra dos archivos independientes — usando el Administrador de agentes
P-1 Avanzado Ejecución de tareas independientes en paralelo — Administrador de agentes
Un practicante experimentado que ha terminado hasta D-1 ejecuta dos tareas mutuamente independientes (redactar topic-a.txt y topic-b.txt) en paralelo en el Administrador de agentes de Antigravity (Escritorio).
Elementos utilizados
Ejecución en paralelo — Escalar al nivel de equipo Ejecución en paralelo
Antigravity (Escritorio) — Administrador de agentes, un agente por Espacio de trabajo

Abra Antigravity y prepare un Proyecto apuntando a harness-lab/ en el Administrador de agentes. Esta vez, en lugar de meter dos agentes en un solo Espacio de trabajo, cree dos Espacios de trabajo separados y asigne un agente a cada uno.

  1. ① Crear el Espacio de trabajo A

    Cree un Espacio de trabajo usando el Modo de nuevo árbol de trabajo.

  2. ② Pegue la oración a continuación en el chat del Espacio de trabajo A y envíela 
    Write a 3–5 sentence draft in topic-a.txt on the topic 'Working from home'.
  3. ③ Crear el Espacio de trabajo B

    Cree otro Espacio de trabajo separado (se recomienda el Modo de nuevo árbol de trabajo). Es una instancia completamente separada del agente del Espacio de trabajo A.

  4. ④ Pegue la oración a continuación en el chat del Espacio de trabajo B y envíela 
    Write a 3–5 sentence draft in topic-b.txt on the topic 'The four-day workweek'.
  5. ⑤ Verificar el progreso de los dos agentes en la Bandeja de entrada

    Mientras ambos agentes trabajan simultáneamente en sus propios Espacios de trabajo, verifique la Bandeja de entrada para ver si hay mensajes que requieran aprobación o retroalimentación, y responda según sea necesario.

No asigne los dos agentes al mismo Espacio de trabajo — compartir la misma carpeta puede causar "superposición cognitiva," donde un agente confunde el contexto de trabajo de otro agente con el suyo propio. Separarlos siempre mediante Espacio de trabajo o árbol de trabajo es la práctica recomendada de Antigravity.

El CLI de Antigravity (agy) puede lograr el mismo efecto abriendo múltiples terminales en lugar del Administrador de agentes del escritorio — trabaje en topic-a.txt con agy en una terminal, y en topic-b.txt con una sesión agy separada en otra terminal, simultáneamente (paralelo entre sesiones). Siempre y cuando las dos sesiones toquen archivos diferentes, no entrarán en conflicto.
